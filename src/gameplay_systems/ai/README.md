# AI System Architecture

This directory contains the modular AI system for the Fantasy Tactics Game. The system determines the actions of AI-controlled units (enemies and allies) based on assigned profiles and the current game state. It is designed for flexibility, testability, and extensibility.

## Core Concepts

*   **AI Profile (`AIProfile`):** A data structure defining an AI's behavioral parameters (archetype, aggression, targeting preferences, thresholds, etc.). See `ai_types.py`.
*   **AI Action (`AIAction`):** Represents a potential action sequence (e.g., move to (X,Y) and attack Unit Z) evaluated by the system. See `ai_types.py`.
*   **Utility:** A numerical score representing the desirability or effectiveness of a potential `AIAction`.
*   **Archetype:** A predefined behavioral pattern (e.g., Charge, Guard, Heal Support, Thief) that dictates how an AI prioritizes actions and evaluates utility.

## Directory Structure & Components

*   **`ai_types.py`**: Defines core data structures (`AIProfile`, `AIAction`) and enumerations (`AIBehaviorType`, `AITargetPriority`) used throughout the AI system.
*   **`ai_profile_manager.py` (`AIProfileManager`)**:
    *   **Responsibility:** Loads, caches, and provides access to `AIProfile` data. Units are typically assigned an `AIProfile` key (string), and this manager retrieves the corresponding profile object.
    *   **Key Methods:** `get_profile(profile_key)`, `load_profiles()`.
*   **`ai_action_evaluator.py` (`AIActionEvaluator`)**:
    *   **Responsibility:** Generates a comprehensive list of all *possible* `AIAction` objects a unit can perform from its current position and reachable tiles. This includes movement, attacks, captures, item/staff usage, interactions (chests, doors), stealing, waiting, etc.
    *   **Dependencies:** Relies heavily on other game systems (`MovementSystem`, `CombatSystem`, `MapSystem`, `InventorySystem`, `StaffSystem`, etc.) to determine valid actions and gather initial context (e.g., combat predictions).
    *   **Key Methods:** `generate_actions(unit, game_state)`.
*   **`ai_action_scoring.py` (`AIActionScoring`)**:
    *   **Responsibility:** Calculates a *base utility score* for each potential `AIAction` generated by the `AIActionEvaluator`. This score reflects general tactical considerations (e.g., damage dealt/taken, healing amount, objective progress).
    *   **Dependencies:** Uses helper functions (potentially from `ai_action_scoring_helpers.py`) for specific calculations.
    *   **Key Methods:** `score_actions(actions, unit, profile, game_state)`.
*   **`ai_action_scoring_helpers.py`**:
    *   **Responsibility:** Contains reusable functions for calculating specific utility components (e.g., calculating utility based on combat prediction, distance to target, terrain safety). Used by `AIActionScoring` and potentially `ArchetypeHandlers`.
*   **`ai_archetype_handler.py` (`ArchetypeHandler` - Base Class)**:
    *   **Responsibility:** Defines the interface for all archetype-specific handlers. Requires subclasses to implement the `refine_actions` method.
*   **`archetype_handlers/`**: Contains concrete implementations of `ArchetypeHandler` for different AI behaviors.
    *   **Responsibility:** Each handler takes the list of actions (with base utility scores) and *refines* them according to the specific archetype's logic and the unit's `AIProfile`. This involves:
        *   Adjusting utility scores (e.g., increasing heal utility for `HealSupportHandler`, decreasing attack utility for `ThiefLootHandler`).
        *   Filtering actions (e.g., removing moves outside a guard zone for `GuardHandler`).
    *   **Examples:**
        *   `charge_handler.py` (`ChargeHandler`): Prioritizes moving towards and attacking preferred targets.
        *   `guard_handler.py` (`GuardHandler`): Prioritizes staying near a post, attacking enemies in range, and potentially filtering out distant moves.
        *   `heal_support_handler.py` (`HealSupportHandler`): Prioritizes healing allies below health thresholds, potentially filtering out offensive actions unless necessary.
        *   `thief_loot_handler.py` (`ThiefLootHandler`): Prioritizes interacting with chests/doors and stealing, adjusting utility for moves towards loot targets.
*   **`__init__.py`**: Makes the directory a Python package.

*(Note: The central orchestration logic, previously in a monolithic `AIManager`, is now typically handled by a higher-level system like a `TurnManager` or `GamePhaseManager` which calls into these AI components during the AI phase.)*

## Flow of Control (Typical AI Unit Turn)

1.  **Initiation:** The main game loop/turn manager identifies the current AI unit whose turn it is.
2.  **Profile Retrieval:** The `AIProfileManager` is queried to get the `AIProfile` for the active unit.
3.  **Action Generation:** The `AIActionEvaluator` is called with the unit and current game state. It generates a list of all valid `AIAction` objects the unit *could* perform.
4.  **Base Scoring:** The `AIActionScoring` component calculates the initial `predicted_utility` for each generated `AIAction` based on general tactical value.
5.  **Archetype Refinement:**
    *   The appropriate `ArchetypeHandler` (based on the unit's `AIProfile.behavior_archetype`) is selected.
    *   The handler's `refine_actions` method is called. It modifies the `predicted_utility` scores and/or filters the list of actions based on the archetype's specific goals and the profile's parameters.
6.  **Action Selection:** The action with the highest final `predicted_utility` score from the refined list is chosen. Ties are broken deterministically.
7.  **Execution:** The chosen `AIAction` is passed to the central `ActionHandler` system for execution within the game state.

This modular design allows for easier testing of individual components (evaluation, scoring, specific archetypes) and simplifies adding new AI behaviors by creating new `ArchetypeHandler` implementations.
