# Project Organization

This document outlines the organization of the Fantasy Tactics Game project codebase after cleanup and reorganization.

## Directory Structure

The project is organized into the following main directories:

- **src/**: Core source code for the game
  - **core_engine/**: Essential game mechanics and systems
  - **gameplay_systems/**: Higher-level gameplay features
  - **ui/**: User interface components
  - **utils/**: Utility functions and helpers
  - **ai/**: Artificial intelligence systems

- **tests/**: Test cases for the game functionality
  - **visual_tests/**: Tests for visual elements and rendering
  - **mechanic_tests/**: Tests for game mechanics
  - **renderer_tests/**: Tests specifically for rendering subsystems
  - **integration_tests/**: End-to-end tests for game features
  - **sound_tests/**: Tests for sound system
  - **ui_tests/**: Tests for UI elements

- **tools/**: Utility scripts and development tools
  - `organize_root_files.py`: Script to organize files into proper directories
  - `check_imports.py`: Tool to verify imports after file reorganization
  - `move_remaining_tests.py`: Script to handle special case files
  - Additional tools for asset generation and development tasks

- **docs/**: Documentation for the project
  - **systems/**: Documentation for game systems
  - **game_mechanics/**: Documentation for gameplay mechanics
  - **archive/**: Historical documents for reference
  - `organization.md`: This document describing project structure

- **assets/**: Game assets such as sprites, sounds, etc.
  - **sprites/**: Visual game elements
  - **sounds/**: Audio files
  - **tiles/**: Map tiles and terrain
  - **ui/**: UI assets

- **data/**: Game data files in YAML/JSON format
  - **chapters/**: Game chapter scenarios
  - **scenarios/**: Test scenarios for AI and mechanics

- **logs/**: Log files generated by the game and tests
  - Various subdirectories for different types of tests

## Root Directory

The root directory has been cleaned up, with only essential files remaining:

- `run_game.py`: Main entry point for running the game
- `launch.sh`/`Launch.bat`: Platform-specific launch scripts
- `setup_venv.sh`/`setup_venv.bat`: Environment setup scripts
- `requirements.txt`: Python dependencies
- `pytest.ini`: Configuration for pytest
- `run_mechanic_tests.sh`: Script to run mechanic tests
- `.gitignore`: Git ignore patterns
- `README.md`: Project overview and getting started guide

## Cleanup Process

The project underwent several cleanup steps:

1. **File Reorganization**: Test files and utility scripts were moved from the root directory to appropriate subdirectories.
   - Visual test files moved to `tests/visual_tests/`
   - Mechanic test files moved to `tests/mechanic_tests/`
   - Renderer test files moved to `tests/renderer_tests/`
   - Sound test files moved to `tests/sound_tests/`
   - UI test files moved to `tests/ui_tests/`
   - Utility scripts moved to `tools/`
   - Log files moved to `logs/`

2. **Special Case Handling**: Files with conflicts (same name in different directories) were handled specially.
   - `test_rescue_mechanics.py` from root was renamed to `basic_rescue_demo.py` and moved to `tests/mechanic_tests/`

3. **Documentation Consolidation**: Various markdown files were consolidated and organized into the docs directory structure.
   - AI research documents were moved to `docs/archive/`

4. **Obsolete File Removal**: Outdated files were removed.
   - Unmaintained `CHANGELOG.md` was removed

## Tools for Organization Maintenance

The project now includes tools to help maintain organization:

- `tools/organize_root_files.py`: Can be run to move misplaced files to their correct locations
- `tools/check_imports.py`: Verifies that moved files still have working imports
- `tools/move_remaining_tests.py`: Handles special cases like file renaming

## How to Add New Files

When adding new files to the project:

1. **Source Code**: Add new game features in the appropriate subdirectory of `src/`
2. **Tests**: Place test files in the relevant test directory based on what they're testing
3. **Tools**: Development scripts and utilities should go in the `tools/` directory
4. **Documentation**: Add documentation in the appropriate docs subdirectory

Avoid adding new files to the root directory unless they are essential launcher or configuration files.
